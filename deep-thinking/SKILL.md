# 深度思考技能 (Deep Thinking)

## 这个 skill 做什么

它是一个**思考前置层**：当用户抛出需要判断/分析/决策的问题时，不直接给答案，而是先在"得出结论前"插入一套对抗快速反应的思考流程，再给出经过审视的结论。

深度思考 ≠ 想得久、想得多。它的本质是**对抗急着下结论的本能**——在给出第一个答案之前，强行插入几道工序：重构问题、清点假设、寻找证伪、推演后果。

它的对立面不是"想得浅"，而是"急着下结论"。

## 何时触发，何时不触发

先做一次**复杂度判断**，决定走全流程还是快速过。不要把每个问题都拖成深度思考，那会让回答又长又烦。

**走全流程的信号**（命中任一即走）：
- 问题有对立面或争议（存在合理反方观点）
- 第一次面对的新问题、新领域
- 影响较大或不可逆（决策、判断、投入资源）
- 涉及因果判断、预测、归因
- 用户给出论断让你评估其成立度
- 用户用了显式唤起命令（见下节）

**可快速过的信号**（不走全流程，正常回答即可）：
- 事实查询（"X 是什么""X 在哪"）
- 明确指令执行（"把文件改成 Y""运行命令 Z"）
- 单一文件读写或短修改
- 闲聊、问候、确认
- 你已经在这个会话里深度思考过同一问题

判断为"快速过"时，直接正常回答，不必提及本流程。

## 显式唤起（随时使用）

用户可以随时用短命令强制触发本流程，**无论问题复杂度如何**：
- "深度思考一下 X"
- "深想一下 X"
- "/deep X"

这是"随时使用"最可靠的路径——自动触发靠 description 短语覆盖，总有遗漏；显式命令是兜底。当用户用这些命令时，即使问题看起来简单，也走完核心 3 步并给带置信度的结论。

## 主动提议机制

当 agent 自己判断"这问题值得深想"但用户**没明说**触发短语、也没用显式命令时，可以主动问一句：

> "这个问题值得深想一下，要不要我走深度思考流程？"

- 只问一次。用户拒绝就正常回答，不再追问。
- 不要闷头触发（会显得啰嗦），也不要错过（会显得浅）。
- 把"是否触发"变成一次轻量协商，而不是两个极端。

这条是为了覆盖"隐式判断需求"——用户抛现象不提问、表达模糊不安、给方案让你"看看"，这些未必命中触发短语，但实际需要深度思考。

## 思考流程：3 核心步 + 4 可选步

核心 3 步**必走**（缺一道就是"伪深度"）。可选 4 步按问题特征启用——不是每个问题都需要全走，按需裁剪避免啰嗦。

### 核心 1：重构问题
不急着答。先用一句话写出"用户真正在问什么"。
- 区分**表象问题**与**根本问题**。用户问"我该不该跳槽"，真正的问题可能是"我为什么在现在这份工作里感到无意义"。
- 必要时重写问题，把模糊问题压成可回答的问题。
- 用 5 Why 穿一层：连续问"为什么"，直到触及根本。
- 产出：一句重构后的问题。

### 核心 2：清点已知与未知
把信息分成四类，不要混在一起：
- **事实**：可被验证、有出处
- **推断**：基于事实的合理推导
- **假设**：未经验证、当作前提在用
- **观点**：价值判断、立场
- 标出**信息缺口**——哪些关键信息缺失。
- **若缺口关键且阻塞判断**：可以主动问用户 1-2 个澄清问题，不要闷头假设。非关键缺口则标注为假设继续。
- 产出：四类清单 + 缺口列表。很多争论其实是把假设当事实，这步就是为了拆穿这点。

### 核心 3：结论 + 置信度
给出结论，但必须标注不确定性。
- 明确说哪部分是**高把握**、哪部分是**中把握**、哪部分是**低把握**。
- 列出**关键假设**：如果这些假设不成立，结论需要重判。
- 列出**重判触发器**：什么新信息出现时应该改变结论。
- 产出：分置信度的结论 + 关键假设 + 重判触发器。**这两项不可省。**

### 可选 A：多框架拆解（问题有多个合理分析角度时启用）
至少用**两个不同框架**看同一问题，单框架必偏。可选框架：
- 第一性原理：剥离所有假设回到公理，从零推导（**可调用 first-principles-decomposer skill**）
- MECE 拆解：切成互不重叠、穷尽的子问题
- 系统视角：反馈回路、二阶效应、激励结构
- 利益相关方视角：谁有动机、谁承担后果
- 时间尺度视角：短期 vs 中期 vs 长期
- 反向思考（invert）：反过来会怎样？怎样做必然失败？

### 可选 B：Steelman 反方（问题有对立面/争议时启用）
把**反对意见**讲到反对者本人都点头认可，再回头评估自己。
- 不要立稻草人，要立铁人（steelman）。
- 列出"反对我结论的最强版本"。
- 找出**自己结论里最可能被推翻的点**——哪个假设最脆弱？哪个推断最跳跃？

### 可选 C：二阶后果推演（决策有连锁/长期影响时启用）
问"然后呢？再然后呢？"。短链思维是浅思考的标志。
- 一阶后果 → 二阶后果 → 三阶/长期
- 注意非线性、反馈回路、意外副作用

### 可选 D：Pre-mortem（决策不可逆或高成本时启用）
假设**结论已经错了**，倒推最可能的原因。
- "假设一年后这个判断被证明是错的，最可能是哪里错了？"
- 列出 top 3 失败原因，每个写一句"如何提前规避或监测"。

> Pre-mortem 和二阶后果的区别：二阶后果推"会发生什么"，pre-mortem 推"我的判断为什么会错"。前者向外看后果，后者向内看自己的盲区。

## 输出模板（固定骨架）

按问题复杂度和用户需求选一种。默认由 agent 判断。

### 精简模式（中等复杂度，用户要答案不要过程）
```
**结论**：[一句话]
- [高把握] ...
- [中把握] ...
- [低把握] ...
**关键假设**：...
**重判触发器**：...
（简注走过哪些步：...）
```

### 完整模式（复杂/重要问题，或用户明确要看思考过程）
```
**重构问题**：...
**已知/未知**：事实=...；推断=...；假设=...；缺口=...
**拆解**（框架1 / 框架2）：...
**Steelman 反方**：...｜自检最脆弱点=...
**二阶后果**：...
**Pre-mortem**：若错，最可能因为=...
**结论**：[分置信度] ... ｜ 关键假设=... ｜ 重判触发器=...
```

不论哪种模式，**结论必须带置信度，必须列出关键假设**。

## 与其他思考 skill 的协作（Integration）

deep-thinking 属于 **thinking-suite** 思维模型集合（集合入口见 thinking-suite；本 skill = 思考前置层）。集合内三个 skill 按"界定 → 分析 → 结论"分工：problem-definition 管"事情到底是什么"，problem-analysis 管"怎么系统分析"，本 skill 管"下结论前该走的工序"。

### 三 skill 路由决策树（单一事实来源，thinking-suite 与另两个 skill 均引用本节）

顺序判断，命中即停：

1. **事情还没弄清**——描述模糊 / 感受与事实混杂 / 接到他人交代没问清 → 交给 **problem-definition**，不猜测补位硬出结论。
2. **问题已清楚、需要系统分析**——根因 / 拆解 / 一堆乱材料 / 排优先级 / 方案验证 / 出汇报 → 交给 **problem-analysis**。
3. **判断/评估类、一轮给结论**——要不要 X / X 对不对 / 你怎么看 / 方案靠谱吗 → 本 skill 走核心 3 步。
4. **收尾回流**：problem-analysis 的分析卡自带把握分与【未查透】，可直接收尾不必回流；problem-definition 界定完、用户只要轻量判断时，回本 skill。

### 歧义裁决（高频冲突）

| 用户说法 | 路由 | 裁决依据 |
|-|-|-|
| "帮我分析 X"（无限定词） | deep-thinking 默认接 | 就地发现问题说不清或需系统分析时，按决策树移交 |
| "系统分析 / 理一理 / 一堆乱材料 / 找根因 / 排优先级 / 用哪个模型" | problem-analysis | 带系统分析限定词 |
| "到底怎么回事 / 这个问题是什么 / 这需求怎么理解" | problem-definition | 问题本身没说清 |
| 模糊不安但有评估对象（"这方案我觉得哪里不对"） | deep-thinking | 对象具体，要评估 |
| 模糊不安且说不清（"氛围很怪，说不上来哪里不对"） | problem-definition | 需先还原事实 |
| "这事怎么跟领导说" | 简短同步 → problem-definition ⑧；正式汇报分析成果 → problem-analysis 场景 16 | 看分析是否已跑过 |

### 与 first-principles-decomposer 的关系
- **不互相替代**：deep-thinking 是流程框架，第一性原理是其中一个拆解方法。
- **调用时机**：deep-thinking 触发后，在"可选 A 多框架拆解"步，若问题适合从原子重建（设计新产品、挑战既有做法、感觉现有方案过度复杂），可调用 first-principles-decomposer 作为其中一个框架。
- **避免抢触发**：用户明说"first principles / 第一性原理 / 从零开始 / break this down"时，让 first-principles-decomposer 主导，deep-thinking 不抢；deep-thinking 在后台仍可提供"置信度标注"和"证伪"的收尾工序。
- 简言之：**deep-thinking 决定"想不想、怎么框定"，第一性原理决定"拆的时候怎么拆到原子"**。

### 可选步 B/C/D 与 problem-analysis 的关系
可选步 B（Steelman）、C（二阶后果）、D（Pre-mortem）对应的专项模型已内置于 problem-analysis（分别对应场景 9/13/12）。轻量判断时在本 skill 内化执行即可；作为系统分析的一部分需要这些模型时，整件事路由到 problem-analysis，不拆开执行。原"等待新增 inversion/pre-mortem-analyst 专项 skill"的扩展计划不再需要。

## 必须避免的反模式

- **假装深度**：用复杂词汇、堆砌框架名掩盖浅薄。框架要用在刀刃上，不是显得专业。
- **思考瘫痪**：永远在分析、不下结论。深度思考的终点是**带置信度的结论**，不是无限犹豫。
- **立稻草人**：把反方观点写成弱智版来反驳。必须 steelman。
- **把假设当事实**：核心 2 就是为了防止这个，不要跳过。

## 边界与不适用

- 不用于心理/精神状态诊断、人格标签、无依据的人身判断。
- 不用于需要专业资质的法律/医疗/财务最终结论——可做思考框架，但必须提示"需咨询专业人士"。
- 不替代事实核查：核心 2 的"事实"必须是可验证的，不能把传言当事实。
- 不用于创意发散/头脑风暴——那是另一种思维（要发散不要收敛），深度思考会显得机械。
- 不用于情感陪伴/倾诉——深度思考会显得冷，此时应先共情再判断。
