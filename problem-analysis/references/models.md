# 16 场景思维模型卡（详细版）

本文件是 `problem-analysis` 的详细参考。SKILL.md 只保留场景地图和执行要点；
这里有每个模型的完整用法、案例演示和**原始 AI 提示词**——提示词可原样复制给任意 AI
（ChatGPT、DeepSeek、豆包、Kimi 都可以），替换〔〕里的内容即可。

★ 高频模型（8 个）：5 Why、逻辑树、MECE、假设-验证闭环、80/20 法则、证伪思维、决策矩阵、金字塔原理。

全程案例：项目还有三周上线，测试报出 40+ 缺陷，客户还在加需求，团队天天加班，
进度几乎不动。缺陷 60% 集中在接口模块，需求已变更 17 次。

# 第一步：定义问题

## 场景 1：问题只有一句话，真因藏在后面 → 5 Why 追问法 ★

**画面**：老板丢来一句"项目要黄了，你去搞定"——这是表象，不是问题本身。真因藏在后面，得一层层挖。

**模型**（源自丰田生产方式）：对表象连续追问"为什么"，直到找到能动手改的根因。

**怎么用**（两条规则）：
1. 每个回答必须是上一句的直接原因，答不上来就去查；
2. 问到能动手改的东西就停。

```Plain
项目要延期 → 为什么？→ 核心模块联调总通不过
→ 为什么？→ 两团队用的接口文档版本不一致
→ 为什么？→ 文档没有唯一负责人，改了没人同步
停：指定接口文档唯一负责人、冻结版本，这就是能改的一层。
```

**AI 提示词**：

```Plain
用 5 Why 追问法帮我分析：对我的问题连问"为什么"，最多 5 次，我每次只答一句，答不上记"待查"别让我猜，问到能动手改的东西就停。我的问题：
```

## 场景 2：所有人都说"显然该这么做" → 第一性原理

**画面**："延期就加人啊，这还用想？"——所有人都这么说的时候，最值得停下来查一查：这个"显然"背后藏着什么假设？

**模型**：剥掉所有默认假设，回到最基本的事实，重新推导问题。

**怎么用**：写下你认定的结论，列出它依赖的每个假设，逐个问"这个假设成立吗？有证据吗？"

```Plain
"项目延期，所以加人"——默认假设是"人手不足是瓶颈"。
剥掉它，回到事实：缺陷 60% 集中在接口模块，是协作问题，加人不解决接口问题。
真正的问题是：接口文档没有唯一权威版本。
```

**AI 提示词**：

```Plain
用第一性原理审视我的判断：〔写判断〕。列出它依赖的所有默认假设，逐个标注"有证据/没证据/想当然"，然后只基于有证据的事实重新定义问题。
```

# 第二步：拆解问题

## 场景 3：问题大而模糊 → 逻辑树 ★

**画面**："项目为什么延期？"——这问题大得没法回答。要先拆成可以逐块检查的小问题。

**模型**（金字塔原理，自上而下分解）：从问题出发，按同一维度逐层拆解成子问题，形成一张分析地图。

**怎么用**：先搭暂定结构，挑证据最多的一支继续往下拆：

```Plain
项目延期
├── 需求问题
├── 资源问题
├── 技术问题
├── 协作问题          ← 证据指向这里，继续往下拆
└── 计划问题
    协作问题
    ├── 接口文档没定稿
    ├── 双方排期不对齐
    ├── 变更没有同步机制
    └── 职责边界不清
```

关键：树是**暂定地图**，不是事实本身——它告诉你去哪里找证据，不替你证明结论。
决策类问题同样适用："要不要申请延期"，按影响、成本、客户关系、团队士气拆解。

**AI 提示词**：

```Plain
用逻辑树帮我拆解问题：〔描述〕。搭一棵暂定逻辑树，3-5 个主分支，同一层同一维度，不重复不遗漏，每支标注"待验证"，然后问我哪支证据最多。大白话。
```

## 场景 4：手里一堆零散材料，看不出头绪 → 归纳法

**画面**：没有明确的问题框架，手里只有缺陷清单、变更记录、排期表、聊天记录——材料一堆，结论零个。

**模型**（自下而上）：从事实、个案、记录出发，归类相似项，归纳出模式，提出待验证假设。

**怎么用**：翻缺陷清单（哪些模块出错、是否反复出现）、变更记录（改了几次、谁提的）、排期表（各方排在什么时间），把相似问题归类：

```Plain
项目卡住的相关事实
├── 缺陷集中在接口模块
├── 需求已变更 17 次
├── 两团队各自排期，互不通气
├── 测试环境三天两头崩
└── 核心成员上周离职
```

归纳出假设：接口联调可能是最大瓶颈。
注意：归纳出的是**模式，不是真相**——模式受样本、口径和观察偏差影响，必须再验证（场景 6、9）。

**AI 提示词**：

```Plain
用归纳法帮我分析材料：〔贴零散材料〕。按相似性归类，找出重复出现的模式，提出 1-2 个待验证假设，并提醒可能受什么偏差影响（样本、口径、观察偏差）。
```

## 场景 5：分支打架，有重叠有遗漏 → MECE 原则 ★

**画面**：图画完了，却越看越乱：这两支好像是一件事？那个重要情况没地方放？

**模型**（源自麦肯锡）：分支之间不重复（Mutually Exclusive），重要范围不遗漏（Collectively Exhaustive），分类口径一致。

**怎么用**：检查三问——
1. 有没有两支其实是一件事？
2. 有没有重要的情况没被任何一支覆盖？
3. 同一层用的是同一个维度吗？

```Plain
"需求蔓延、张三离职、计划太紧"不该放在同一层——分别是现象、人和原因。
修正：按"原因"维度重组为需求管理、人员管理、计划管理。
```

**AI 提示词**：

```Plain
用 MECE 检查我的分类：〔贴分类〕。指出重复项、遗漏项和维度混乱的地方，然后按同一维度重新组织。
```

## 场景 6：问题重要又复杂 → 假设-验证闭环 ★（全文核心方法）

**画面**：重要决策、证据复杂——只拆树，容易围着错误假设找证据；只理料，容易看了很多、判断很少。

**模型**（科学方法）：归纳提假设，演绎搭结构，证据做验证，行动后复盘，循环往复。

**怎么用**：把两种入口连成闭环：

```Plain
归纳：发现模式（缺陷集中在接口处）
  ↓
演绎：搭原因树（文档/排期/变更/环境）
  ↓
验证：找证据（文档版本确实不一致、排期确实错开）
  ↓
输出：结论 + 行动 + 验证指标
  ↓ （行动后新事实进来，进入下一轮循环）
```

关键在最后一环：**闭环不是分析完就结束，而是"分析 → 行动 → 验证 → 再分析"持续转下去**。

**AI 提示词**：

```Plain
带我走假设-验证闭环：① 从我的材料归纳模式；② 演绎出原因树；③ 列出每支需要的验证证据；④ 输出"结论-证据-行动-验证指标"四件套。我的问题和材料：
```

## 场景 7：候选原因都说得通，锁定主因 → 反事实检验

**画面**：文档没定稿、排期不对齐、环境不稳定——三个原因都有证据，都说得通。资源只够修一个。

**模型**：问一句"如果这个原因不存在，问题还会发生吗？"

**怎么用**：还会发生，说明它不是主因；不会发生，大概率就是它。

```Plain
如果接口文档版本统一了，联调还会卡吗？——不会，主因确认。
如果测试环境更稳定，联调还会卡吗？——还会，环境不是主因。
```

比"感觉是它"硬得多：反事实把因果链逼到了可证伪的墙角。

**AI 提示词**：

```Plain
用反事实检验帮我锁定主因。我的候选原因：〔列出来〕。对每个原因问我："如果它不存在，问题还会发生吗？"根据我的回答判断哪个是主因，哪个只是伴随现象。
```

## 场景 8：问题几十条，资源只够打一两个 → 80/20 法则 ★

**画面**：缺陷清单一百多条、问题几十类，每类都派人查等于哪类都查不透。

**模型**（帕累托法则）：少数原因造成多数结果。找到那 20% 的问题源，解决 80% 的后果。

**怎么用**：把问题按来源统计排序，找到贡献最大的少数来源。

```Plain
缺陷 60% 集中在接口模块——先集中火力解决接口文档问题，其他缺陷放第二批。
不要平均用力。
```

**AI 提示词**：

```Plain
用 80/20 法则帮我排优先级。我的问题清单：〔列出来〕。统计每类问题的占比，指出贡献最大的少数来源，告诉我集中火力先解决哪个，其余怎么放。
```

# 第三步：验证与决策

## 场景 9：证据越攒越多，越看越觉得自己对 → 证伪思维 ★

**画面**：材料越查越顺，每条新证据都支持你的判断——这不是好事，是危险信号：你可能只是在收集认同。

**模型**（卡尔·波普尔）：一个结论必须是可以被推翻的；主动找反例，比继续找支持更有价值。

**怎么用**：规则——**一条反例顶五条支持**。

```Plain
"缺陷都是文档版本问题"——反例：环境崩溃导致的缺陷与文档无关。
找到反例不是坏事，是把结论推向更准。
```

配套证据三问：
1. 谁给的（来源可信吗）？
2. 全吗（没出问题的看了吗）？
3. 口径一致吗（时间范围对齐吗）？

**AI 提示词**：

```Plain
用证伪思维审我的结论：〔写结论和证据〕。先对每条证据问：谁给的？全不全？口径一致吗？然后主动找反例：给出三个可能推翻它的方向，一条反例顶五条支持。
```

## 场景 10：结论要拍了，心里没底 → 概率思维

**画面**：明天就要定方案，你说"应该差不多"——"差不多"是多少？敢押多少筹码？

**模型**（贝叶斯更新）：结论不是一个定论，是一个概率；每条新证据都应该更新它。

**怎么用**：给结论标一个百分比：

- 50% 以下：继续查，别汇报；
- 50% 到 80%：可写进分析，标注"待确认"；
- 80% 以上：可以作为行动依据。

更新规则：每出现一个反例，先砍 20 分，不许找借口加回去。

**AI 提示词**：

```Plain
用概率思维评估我的结论：〔写结论〕。证据：〔列证据〕。给结论打把握分（百分比），列出扣分项（反例、口径不一致、来源单一），不到 80% 告诉我还差什么。
```

## 场景 11：怕漏了相关方的信息和反应 → 换位思考

**画面**：分析做完自己很满意，但客户会怎么想？开发会怎么反弹？管理层买不买账？

**模型**（视角切换）：站在每个相关方的位置，识别他们的目标、约束和信息差。

**怎么用**：列出相关方，逐个回答三个问题：

1. 他的目标是什么？
2. 他的约束是什么？
3. 他手里有什么我不知道的信息？

```Plain
客户关注按期上线、开发关注需求稳定、测试关注质量、管理层关注成本
——每个角色的信息差，都是你分析的盲区。
```

**AI 提示词**：

```Plain
用换位思考补全我的分析：〔描述问题和当前判断〕。列出所有相关方，对每个角色分析：目标、约束、他手里可能有什么我不知道的信息，我的分析缺了谁的信息。
```

## 场景 12：方案怎么看都没毛病，反而心里发虚 → 逆向思维

**画面**：方案推演了一遍，处处顺滑——太顺了，反而可疑。总有什么没想到。

**模型**（Inversion，查理·芒格）：不要想"怎么让它成功"，反过来想"什么会让它必然失败"。

**怎么用**：失败预演——列出三个最可能让方案失败的方式，逐个检查现在的方案防住了吗。

```Plain
"冻结需求就能按期"——反过来想：什么情况下冻结需求反而延期？
客户暗中绕过变更流程；关键需求被误砍，上线即事故。
防住这两条，方案才成立。
```

**AI 提示词**：

```Plain
用逆向思维检验我的方案：〔写方案〕。反过来想：列出三个最可能让它失败的方式，逐个检查我的方案有没有防住，缺哪条补哪条。
```

## 场景 13：行动就要定了，怕连锁反应 → 二阶思维

**画面**：方案本身没问题，但世界不是静止的——你动了，别人也会动。怕的就是连锁反应。

**模型**（霍华德·马克斯）：想到行动的后果，还要想到后果的后果。

**怎么用**：问两次"然后呢"，每一层的答案写下来：

```Plain
准备做：冻结所有需求变更
然后呢？→ 客户口头答应，私下继续找产品提
再然后呢？→ 变更绕过流程进来，两周后需求又失控
结论：冻结要客户签字确认，同时留变更通道（每周一次评审）
```

一阶思维只看"做了会怎样"，二阶思维看"别人对我做的会怎么反应"。
第二个"然后呢"里有不能接受的，回去改方案。

**AI 提示词**：

```Plain
用二阶思维推演我的行动：〔描述〕。问两次"然后呢"，每步答案写下来，重点写相关人会怎么反应。第二个"然后呢"里有不能接受的结果，就帮我改方案。
```

## 场景 14：能做的事十几件，先做哪件 → 决策矩阵 ★

**画面**：分析出一堆行动，每件都有人说重要，每件都说自己急。

**模型**（影响×难度四格）：每件行动打两个分：影响（解决多疼的事）1-5，难度（好不好落地）1-5。

**怎么用**：

```Plain
        难度低                难度高
影响大   马上做（本周）        排期做（立项、要资源）
影响小   顺手做                写进"不做清单"
```

冻结接口文档：影响大、难度低——本周做。重构架构：影响大、难度高——立项。
"不做清单"要写下来同步给相关人，否则半年后同样的事又会有人提一遍。

**AI 提示词**：

```Plain
用决策矩阵帮我排行动：〔列清单〕。给每件打影响分和难度分（各 1-5），放进四格（马上做/排期做/顺手做/不做清单），告诉我先做哪件，为什么。
```

# 第四步：收尾表达

## 场景 15：总想"再查一点更稳"，交不出手 → 沉没成本

**画面**：已经查了一周，推翻重来很心疼；总觉得再多查一天就更稳——但 deadline 不等人。

**模型**：已经投入的时间不应影响"继续还是停止"的判断；判断标准是边际——再查下去，结论会变吗？

**怎么用**：三条停止线，满足任何一条就交：

1. 剩下的疑问已经不影响结论方向；
2. 再给一天，结论会变吗——不会；
3. 到时间了：带着不确定交结论，没查透的单独列一节。

> 剩下的不确定性，用行动后的验证指标来补。

**AI 提示词**：

```Plain
用沉没成本原则判断我该不该停：〔分析现状、已投入多少、还剩什么疑问〕。只看边际：剩下的疑问影响结论方向吗？再查一天结论会变吗？没查透的列出来，该交就让我交。
```

## 场景 16：分析做完了，明天要汇报 → 金字塔原理 ★

**画面**：分析做了两周，材料几十页——老板只给你五分钟，从哪说起？

**模型**（结论先行）：先说结论，再给支撑；先讲最重要的，再讲次要的。

**怎么用**：按对方关心的顺序组织，不按你分析的顺序讲：

```Plain
结论：最大瓶颈是接口文档未冻结，双方各自返工。
证据：缺陷 60% 集中在接口模块；文档改过 5 版，双方使用的版本不一致。
行动：冻结接口文档 v2.0，指定唯一负责人；建立变更同步机制。
验证：一周后接口缺陷占比是否降到 30% 以下。
```

四段式：结论 → 证据 → 行动 → 验证指标。

**AI 提示词**：

```Plain
用金字塔原理帮我组织汇报：〔贴分析结论和证据〕。输出四段式：结论（一句话）→ 证据（三条以内）→ 行动 → 验证指标。结论先行，大白话。
```
