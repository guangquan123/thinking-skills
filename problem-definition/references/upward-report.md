# 向上沟通模块（界定完成后的同步产出）

适用：问题界定完成后，用户需要向某人**简短同步**此事——领导、客户、合作方、导师、家人均可。核心逻辑不变：对方只关心三件事——出了什么事、影响多大、需要他干什么。

**按对象调节奏**：对直属领导/熟悉内情的人，三行版直接发；对高层/外部对象，先口头或消息简短同步、对方追问再展开；对不掌握背景的人，行 1 里多给半句背景。原则只有一个：**默认最简，对方要再给**。

## 两版模板（先简后繁，默认先给最简版）

### 30 秒口头版（三句话）

1. **事 + 影响**：X 出了 Y 问题，直接影响 Z。
2. **已做**：我们已经做了 A、B。
3. **要他干什么**：现在需要您 C。

### IM / 短消息版（三行）

```
行1（事 + 影响）：X 项目 XX 出现 YY，直接影响 ZZ。
行2（已做）：已经做了 A；B 也已沟通知情。
行3（要他做什么）：目前就差 C，需要您 D。
```

**压缩规则**：原因细节、风险推演、备选方案全部砍掉——留作追问时回答，不占第一屏。

**一句话检验标准**：对方看完不用追问"所以你要我干嘛"，就算说清楚了。

⚠️ 常见错误：先给领导一版六段式完整报告（现状/原因/影响/动作/风险/请求）。正确顺序是反过来——**先给三行版，对方要细节再展开**。

## 追问预案（汇报前必做）

预判 3 个最可能被问的问题，每个准备**标准答案 + 兜底句**：

| 高频问题 | 答法要点 |
|-|-|
| "到底什么时候能解决？" | 给"**何时能确定**"的时限，不给自己没底的日期——日期再跳，你的信用就没了 |
| "影响多大？会不会耽误 XX？" | 必须有数字（节点日期、剩余缓冲天数）；空口说"影响可控"只会让对方更不放心 |
| "干系人（客户/合作方）什么反应？" | **坏消息主动亮**：对方从你嘴里听到 = 你掌控局面；从别的渠道听到 = 你在隐瞒 |

**兜底句模式**："现在卡在 X，我在做 Y，**Z 日前给您准信**。"

## 汇报前准备清单（4 项，5 分钟）

1. 最关键敞口的**确定时限**（何时能有答案——来自步骤 3 的"未闭环的一环"）
2. 受影响节点的**数字**（原计划日期 + 剩余缓冲）
3. 补救动作的**执行时间表**（如款项到账时间）
4. **原因的统一说法**（和相关方先对齐，不带未核实的原因上会）

## 实战示例（服务器硬件延期）

**三行版：**
> 领导，X 项目服务器硬件供应商延期，节前到不了货，日期还在协商，直接影响现场部署。
> 公司已定垫资付款催发货，客户已沟通知情。
> 目前就差付款到位这步，需要您推一下节奏。

**追问预案：**
- Q"到底什么时候能到货？" → "供应商本周内给准确日期。按垫资付款进度，预计节后 X 个工作日内到货，一有确切消息我第一时间报您。"（兜底："现在卡在付款到账节奏，款一到位供应商就排产，X 日前给您准信。"）
- Q"影响多大？" → "卡的是现场部署，原计划 X 月 X 日进场，还剩 X 天缓冲。到货日期一确认我马上重排部署计划。"（没数字这题就答砸了）
- Q"客户什么反应？" → "已沟通，客户知情、接受节后安排。客户内部已上报他们的分管领导，到货日期一确认我们就主动同步客户。"（"客户已上报"必须主动讲，不能等领导从别的渠道听到）

**收尾口诀：Q1 给时限、Q2 给数字、Q3 主动亮。三个都做到，汇报就是加分而不是交差。**
